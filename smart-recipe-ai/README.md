# Simmer --- Smart Recipe AI

Simmer is an AI-powered cooking assistant that helps users discover
dishes, find recipes based on pantry ingredients, and get complete
cooking instructions through a conversational interface.

It combines a React frontend with a FastAPI backend, ChromaDB vector
search, local Sentence Transformers embeddings, and Groq-powered recipe
generation.

## Features

### 1. Pantry-based recipe recommendations

-   Add ingredients available in your kitchen.
-   Retrieve and rank up to five matching recipes.
-   Use semantic retrieval together with ingredient matching.
-   See which pantry ingredients are used, which are not needed, and
    which recipe ingredients are missing.

### 2. Conversational recipe assistant

Ask for a dish directly, such as: - `Chicken biryani` -
`Afghani chicken` - `Pepper gravy` - `Lemon chicken`

You can also ask for a group of dishes, for example: -
`Authentic chicken curry` -
`Give me five regional chicken curry options`

The assistant can return a specific recipe or a list of recipe
suggestions. Recipe responses are structured with measured ingredients,
servings, preparation and cooking times, and step-by-step methods when
available from the curated recipe data or generated by the configured
LLM.

### 3. Optional live recipe references

Tavily integration is optional. When `TAVILY_API_KEY` is configured, the
backend can search for live recipe references. Without it, the
application can still use its local recipe collection and Groq
generation.

### 4. Local vector database

-   Recipe text is embedded with
    `sentence-transformers/all-MiniLM-L6-v2`.
-   ChromaDB stores recipe vectors and metadata locally.
-   Run the ingestion script again whenever the recipe dataset changes.

## Requirements

Install the following before starting:

-   Python 3.10 or newer (Python 3.11 is a good choice).
-   Node.js 20 or newer.
-   npm.
-   A Groq API key.
-   Internet access for installing packages and downloading the
    embedding model.

Tavily is optional.

## Installation on Windows

Open two terminals in VS Code: one for the backend and one for the
frontend.

### 1. Set up the backend

In the first terminal:

``` powershell
cd backend

python -m venv venv
.\venv\Scripts\Activate.ps1

python -m pip install --upgrade pip
python -m pip install -r requirements.txt

Copy-Item .env.example .env
```

If PowerShell blocks activation scripts, allow activation for the
current terminal session:

``` powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\venv\Scripts\Activate.ps1
```

### 2. Configure environment variables

Open `backend/.env` and add your Groq API key:

``` env
GROQ_API_KEY=your_groq_api_key
GROQ_MODEL=openai/gpt-oss-20b
GROQ_TIMEOUT_SECONDS=25
TAVILY_API_KEY=
FRONTEND_ORIGINS=http://localhost:5173,http://127.0.0.1:5173
PRELOAD_EMBEDDING_MODEL=true
RETRIEVAL_CANDIDATES=20
```

Get a Groq API key from [Groq Console](https://console.groq.com/keys).

`TAVILY_API_KEY` is optional. If you want live recipe-reference search,
add your Tavily key. Do not put API keys in frontend files or commit
`.env` to Git.

### 3. Index the recipe collection

Run this from the `backend` directory with the virtual environment
activated:

``` powershell
python ingest.py
```

This loads `backend/app/data/recipes.json`, creates embeddings, and
stores the recipe records in the local ChromaDB collection.

Run `python ingest.py` again whenever you add or edit recipes in the
JSON dataset.

### 4. Start the backend API

Still inside `backend`:

``` powershell
uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

Useful backend URLs:

-   API root: http://127.0.0.1:8000/
-   Health check: http://127.0.0.1:8000/api/health
-   Interactive API docs: http://127.0.0.1:8000/docs

Keep this terminal open while using the frontend.

### 5. Set up the frontend

In the second terminal:

``` powershell
cd frontend
npm install
npm run dev
```

Open the local URL printed by Vite, usually:

http://localhost:5173

If the backend is running at a different address, create
`frontend/.env`:

``` env
VITE_API_URL=http://127.0.0.1:8000
```

Restart the Vite development server after changing frontend environment
variables.

## How the RAG pipeline works

1.  **Recipe ingestion:** Recipes are loaded from
    `backend/app/data/recipes.json`.
2.  **Document preparation:** Recipe names, cuisine, meal type,
    ingredients, timing, and other searchable fields are assembled into
    text.
3.  **Embedding generation:** Sentence Transformers converts recipe text
    into vectors.
4.  **Vector storage:** ChromaDB stores vectors, documents, and
    metadata.
5.  **Query embedding:** Pantry ingredients or a search query are
    converted into a vector using the same embedding model.
6.  **Retrieval and ranking:** ChromaDB retrieves candidates; the
    backend applies ingredient matching and ranking logic.
7.  **Generation:** Groq can generate recipe explanations or structured
    recipes using the request and retrieved/local context.
8.  **Frontend display:** React renders recommendations, pantry
    summaries, recipe details, and assistant responses.

## Troubleshooting

### PowerShell says `venv` or `Activate.ps1` cannot be found

Make sure the terminal is inside the `backend` folder. If the `venv`
folder does not exist, create it:

``` powershell
python -m venv venv
```

Then activate:

``` powershell
.\venv\Scripts\Activate.ps1
```

### `Cannot reach Simmer` or `ERR_CONNECTION_REFUSED`

The frontend cannot reach FastAPI. Start the backend in a separate
terminal and confirm that this URL opens:

http://127.0.0.1:8000/api/health

Also check `VITE_API_URL` in `frontend/.env` if you have configured a
custom backend URL.

### Groq returns `model_not_found`

Check that `GROQ_MODEL` in `backend/.env` is a model currently available
to your Groq account. Model availability can change. Refer to the [Groq
model documentation](https://console.groq.com/docs/models).

### Hugging Face Hub unauthenticated warning

The embedding model can often download without a Hugging Face token. The
warning is about Hub rate limits; it is not by itself proof that
embedding generation failed.

### Recipes are missing or outdated

Run the ingestion command again from `backend`:

``` powershell
python ingest.py
```

### Frontend changes are not appearing

Save the changed files and check the Vite terminal for compile errors.
Restart `npm run dev` if needed. Hard-refresh the browser with
`Ctrl + Shift + R`.

## Security and data notes

-   Never commit `backend/.env` or expose your Groq/Tavily keys in
    React.
-   Keep `backend/venv/`, `backend/chroma_db/`, and
    `frontend/node_modules/` out of version control.
-   The recipe dataset is a local starter collection; recommendation
    quality improves as you add reviewed recipes.
-   AI-generated cooking instructions should be checked for dietary
    restrictions, allergies, ingredient substitutions, and safe food
    handling.
-   For poultry, use a food thermometer and cook to a safe internal
    temperature of 74°C / 165°F.

## Development notes

-   Backend settings are read from `backend/.env` by
    `backend/app/config.py`.
-   The frontend API client is in `frontend/src/services/api.js`.
-   Recipe records are maintained in `backend/app/data/recipes.json`.
-   ChromaDB data is persisted under `backend/chroma_db/`.
